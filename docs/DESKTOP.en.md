# Windows, Apple Silicon and the expanded editor

Document ID: HWI4U-DESKTOP · Version: 1 · 2026-10-18

Source candidate 0.15.0, schema 22 unchanged. FR-012 targets Windows 11 x64; FR-029 targets native Apple Silicon (M1 and later) on macOS 14 or later. Intel Macs, Windows ARM, iOS and Android are outside this package. Automated platform checks and end-user acceptance are different: the CI targets are Windows Server 2025 x64, macOS 14 ARM64 and Ubuntu 24.04; a successful runner does not verify every PC, MacBook, display, OS release or security configuration. Current run evidence belongs in the pull request. First-install/desktop integration and user review on the actual target computer remain required before calling that installation accepted.

## Install and open

This is a **source-client package**, not a bundled Python EXE, signed installer or notarized Mac application. It needs Python 3.14 installed from [python.org](https://www.python.org/downloads/), internet access for the pinned FOSS PySide6 dependency on first install, and a writable local installation folder. A virtual environment is an isolated Python dependency folder; the installer creates `.venv` and leaves system packages unchanged. Do not move/delete the installation folder while using its launchers. Use a local filesystem supporting hard links for the current backup publication mechanism, such as NTFS/APFS; cloud-sync/network/FAT data folders are not qualified. Backups and attachments require independent protection; ordinary ZIPs are not encrypted.

**Windows:** extract `hwi4u-source-client.zip` into a permanent user-writable folder. Verify `py -3.14 --version` in a terminal; if unavailable, install Python 3.14 with its launcher first. Double-click **Install HWI4U.cmd**. On success, use **Start HWI4U.cmd** or **Start HWI4U TEST.cmd**. The launchers set UTF-8 mode and use `.venv\Scripts\python.exe`. Initial data is under `%LOCALAPPDATA%\HWI4U`, with TEST in a separate dataset. Console output stays available for installation errors; no administrator rights are requested by HWI4U.

**Apple Silicon:** use native ARM64 Python 3.14 and a normal native Terminal, not an Intel/Rosetta interpreter. Extract the package to a permanent user-writable folder, then open **Install HWI4U.command**. If executable permission was lost during transfer, run `chmod +x "Install HWI4U.command"` in that folder, then `./"Install HWI4U.command"`. Setup creates **HWI4U.app** and **HWI4U TEST.app** in the same folder; double-click the desired app, or add it to the Dock. These are local launcher bundles pointing to the installed virtual environment, not self-contained binaries; moving just the app breaks its reference. macOS may require explicit approval for downloaded scripts/apps; do not disable system security. Initial data is under `~/Library/Application Support/HWI4U`, with a separate TEST dataset.

Existing valid managed workspaces are never reset: reinstalling stages new source to TEST and keeps production pinned. An unfamiliar existing data folder stops installation without overwriting it. Initial setup creates an empty inventory; it does not download a populated database from GitHub. Transferring an existing inventory requires a verified **Full backup** including attachments and reviewed restore into a new directory, not copying an open SQLite file. See [recovery](RECOVERY.en.md). Current `manage.py init` refuses existing directories; do not replace generated files manually to force an import. Shared multi-machine editing/offline synchronization remains FR-014, not a feature of these independent clients.

Technical installation alternative: `python3 install_desktop.py` on macOS or `py -3.14 install_desktop.py` on Windows. `--skip-pip` is only for an existing `.venv` already containing exact dependencies, not an offline dependency bundle. Setup errors leave diagnostic files; do not delete private data to retry. Keep older installation/source and verified full backups until a new candidate is accepted. New package versions have a new isolated environment; do not rename an existing venv.

## Expand a device

Double-click a saved row in the left list. A maximized device-only window opens; quick editing remains in the original window. Repeating the double-click focuses the existing editor for that full device ID. All property sections, location editing, photos/references, validation and backups use the existing form/store. New-device navigation and list filters are hidden in this window; Refresh keeps the same device. Save refreshes another clean view; another view's pending edits stay intact, and a stale save is rejected. Cancel/Refresh lets you reload the saved record. If the device is deleted elsewhere, its clean expanded view disables editing instead of turning into a new-device form. Immediate attachment/library operations retain their existing save semantics.

Closing an expanded window checks its edits. Closing the main client, **Quit HWI4U**, or **Apply update** checks all open editor forms. Save/Discard/Keep editing retains its normal meaning; Keep editing prevents closure/restart. Language switching updates both views while preserving user values. No database schema migration is added by these three requests; upgrading from older schemas still follows earlier managed migrations.

## Validation and package creation

Use `python -m venv .venv`, install `requirements.txt` inside it, then `QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests` (on Windows set the environment variable before running). Native smoke: `python tools/native_smoke.py --output dist/smoke`; it selects Cocoa on macOS, Windows Qt on Windows, and offscreen on Linux, and uses temporary fictional data only. It verifies workspace creation, expanded/quick editing, language switching, full-backup restore and Unicode export, recording architecture/Qt backend and synthetic screenshots. Source ZIP: `python tools/package_source.py --output dist/hwi4u-source-client.zip`. Output must not already exist. The package includes only allowlisted code/docs/tests, preserves script permissions/line endings, and omits private data, photos, drawings, venv and runtime state. GitHub artifacts expire after 14 days; retain source and independent backups locally. Signing/notarization and a self-contained binary installer remain future work.
