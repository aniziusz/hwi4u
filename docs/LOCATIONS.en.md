# Guided device location

Document ID: HWI4U-LOCATIONS · Version: 1 · 2026-10-18

FR-025, source 0.14.0/schema 22, candidate for TEST review. Production acceptance is separate. This implements the Guided form design; drawing import, automatic floor-plan selection, X/Y calibration and graphical marker placement remain a later stage. DXF compatibility needs a sample with confirmed units/origin; no CAD support is claimed.

1. Select a device and choose **Guided location…** below the additional location text.
2. Choose Recorded location, Unknown or Not applicable / portable. No device type automatically determines portability.
3. Reuse an existing place or enter optional building/site, floor/storey and room. New location clears the dialog fields. Reusing a place copies its address/building/floor/room and clears precise placement, height and notes so old placement is not accidentally assigned to a different room.
4. Enter this device's position/wall, optional height in metres and height reference. Both `1,8` and `1.8` work; height is non-negative, at most 10000 m. With a height, choose above finished floor, above ground level or Other with an explanation in notes. No height means no height reference. Each text field accepts single-line Unicode up to 200 characters.
5. Expand **Address and additional notes (optional)** for country, postal code, city, street, house number and placement notes. No hierarchy level is compulsory; a shelf description alone can be recorded. Check the combined preview.
6. **Use location** validates and returns pending values to the device form. **Save device** writes all form changes atomically with a checked pre-save backup. Cancel in the dialog keeps its previous values; Cancel changes in the device form follows the normal unsaved-change prompt. Opening or cancelling never creates places.

Changing one device never renames a shared place or moves others. Places are immutable snapshots, reused when all canonical field values match exactly; choosing different fields creates another place only on device save. Unused places remain available; global rename/delete is intentionally not supplied. Free-text floor labels avoid forcing basement/ground-floor numbering conventions. Suggested floor names follow the dialog language; stored values remain literal. User-entered locations are user reports, not independently verified measurements.

Existing `devices.location` text is retained without parsing in migration 022. It remains independently editable as **Location text / additional description**, with its existing 200-character limit; normal device-save whitespace validation still applies. The new structured state starts Unknown even when historical text exists. Neither field silently replaces the other. Search includes both. Export includes `location_places`, `device_locations`, `device_location_history` in JSON/SQL/CSV; external destination profiles remain planned. History records previous/new structured values, UTC time, `user_entry` source and `user_reported` verification. It survives device deletion; deletion backup/history includes placement. Stable device IDs and other data are retained.

For a repository-managed private workspace: `python manage.py publish --workspace /absolute/private/workspace`, then `python manage.py test --workspace /absolute/private/workspace`. In the TEST client use Apply update, or start TEST normally when closed. The managed updater performs 21→22 under a write reservation after a verified full backup; busy writers defer, failed migrations roll back. No forced application closure or manual live SQL is required. Do not open the new database using an old client. Keep production pinned until exact candidate acceptance; never copy TEST records into production. See [recovery](RECOVERY.en.md). No schema downgrade is supplied; recover a verified earlier full backup to a new directory with the matching earlier release, preserving newer files for review.

Validation procedure: `QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests`. Targeted tests cover height validation, place reuse/move isolation, stale saves, backup failure, pending/cancel/language behavior, search, 21→22 preservation, immutable history and full-backup restore. Offscreen Qt checks are Linux checks; Windows/mobile support is not established. Production deployment is not inferred from tests. Keep source and private data in independent backups; same-disk snapshots alone are insufficient.
