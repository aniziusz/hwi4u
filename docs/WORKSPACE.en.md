# Device list, roles and adaptive workspace

Document ID: HWI4U-WORKSPACE · Version: 1 · 2026-10-19

HWI4U 0.16.0, schema 23. Implements FR-030, FR-031, FR-032, FR-033 and FR-035 in TEST; production acceptance is separate. FR-034 is a duplicate of the already implemented device search. This guide supersedes older single-choice list filters and the original full-width one-column expanded editor.

Use **Group by…** above the device list to choose zero, one or two ordered grouping levels. Click a group heading (or activate it with the keyboard) to collapse/expand it. Grouping does not modify device data. Role groups can display a device more than once; the counter reports unique matching devices. Unknown values have a separate group. Header clicks sort rows within groups; purchase prices sort numerically. Sorting and filtering retain the underlying UUID identity, so double-click opens the selected device even after reordered or repeated rows.

Use **Columns…** to tick visible existing properties and reorder them by dragging, Move up/down, or Restore defaults. Headers can also be dragged or resized directly. Hiding does not delete database fields. At least Name or Short ID remains visible. Available columns include roles, free/structured location, building/floor/room, hostname, MAC/IP values, dates, purchase details and full UUID. Multi-address values are combined for display; grouping is limited to useful categorical fields. View preferences (column visibility/order/widths, grouping and applied checkbox filters) are local JSON beside the selected database, named client-view-production.json or client-view-test.json. Separate TEST datasets have separate preferences. They are not inventory records, are not synchronized, and are not included in inventory backups; copy preference JSON separately if wanted. Search text, temporary grouping-collapse state and header sort direction are not persisted. Malformed preferences fall back to defaults without touching the database.

Use **Filters…**, choose a column, then use the searchable checkbox list. Apply commits the selection; Cancel leaves it unchanged. Search within the checklist hides choices without changing their checks. Select all checks current options; No restriction removes that column filter and includes future values; Clear selection intentionally matches no devices. Unknown/blank is a separate choice. OR applies within a field, AND between fields and the text search. Counts reflect other active filters; already selected zero-count values remain available. Group/type multi-filters are independent and never silently discard each other's selections. **Clear filters** clears column filters and text search. The adjacent summary shows unique matching/total devices and active restrictions. The original hidden single-choice controls remain only as compatibility plumbing; normal interaction uses the checkbox filters.

**Roles** in either device editor opens a multi-select catalogue. Empty means not recorded. Initial choices include firewall, router, VPN gateway, server, backup/file server, wireless access point, network switch, home automation controller, monitoring, client and media player. These are optional user-reported purposes, not discovered facts. Add role extends the shared catalogue immediately with a pre-change backup; cancelling role assignment does not undo a new catalogue choice. Names normalize whitespace/case and allow up to 60 printable characters; existing choices are reused. Assignments remain pending until Save device; Cancel restores saved assignments. Role changes preserve device UUID, short ID and primary type/group. Roles have immutable before/after history. The migration from 22 creates no assignments for existing devices. No particular device's actual roles are inferred from its name or installed software.

Double-click a device for the **adaptive expanded workspace**. The main quick editor remains. An expandable left tree locates/highlights a tile; collapsing a navigation branch does not hide the form tiles. General, location, purchase/lifecycle, state/condition, network, software, interfaces, protocols, photos, manuals and evidence remain available together. Columns automatically reflow from one to four according to available logical width; display scaling and font metrics affect capacity. Scroll to remaining tiles as needed; long assessment tables are retained, rather than cut down to the simplified design preview. Save/Cancel stay below the scrollable workspace. Resizing, tree selection and language switching retain pending values. Existing immediate-save attachment/source-library semantics remain; these actions are not undone by Cancel device changes.

Updates use the managed Apply update/restart workflow: leave a running client pinned while code is edited. An active session/write lock defers an upgrade; it never authorizes replacing a populated database. The update takes a verified full backup and applies migration 023 transactionally. Production remains pinned until acceptance. No TEST records are copied to production. Downgrading an already migrated database is refused; restore the verified pre-update full backup into a new directory using the recovery guide, then open it with the corresponding earlier release. Do not delete role tables or edit user_version to simulate rollback.

Validation uses disposable fictional inventories: prior-schema row/ID preservation, role history and stale saves, backup-failure rollback, grouping/filter identities and unique counts, preference persistence, responsive editor and multilingual pending values. Full-suite and platform outcomes belong in the review/installation receipt; a configured workflow alone does not prove success. The native smoke also checks role persistence and grouped lists before backup/restore and Unicode export. Actual display acceptance remains with the user.
